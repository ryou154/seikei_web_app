# 担当3: 共通ナビゲーション・認証導線・QA 実装指示書

## 目的

分割された各画面を迷わず移動できるようにし、ログイン状態、スマートフォン表示、主要機能の回帰をまとめて保証する。

## ブランチ

`feature/navigation-qa`

作業開始前に `main` を最新化し、このブランチを作成する。`main` へ直接pushしない。

## 担当範囲

- 共通ナビゲーションを作成する。
- ログイン、シミュレーション、履歴、クリニック、アカウントの移動経路を統一する。
- 現在の画面を `aria-current="page"` で示す。
- ログイン中のメール表示とログアウト操作を共通化する。
- 未ログインで保護画面を開いた場合は `login.html` へ戻す。
- ログイン成功後は `app.html` へ移動する。
- ログアウト・アカウント切替時に画面上の画像と結果を消す。
- PC、iPhone相当、Android相当の幅で表示確認する。
- 認証、画面遷移、非公開ファイル、履歴APIの自動テストを追加する。
- チーム用の手動確認表を作成する。

## 推奨ファイル

- `navigation.js`
- `navigation.css`
- `tests/navigation.test.js`
- `docs/QA_CHECKLIST.md`

各HTMLへの変更はナビゲーション読込と最小限のコンテナ追加に限定する。

## 必須テスト

- `/` から `login.html` へ移動できる。
- 許可済み・確認済みユーザーだけが `app.html` を利用できる。
- 未確認メール、許可外メール、期限切れトークンを拒否する。
- ログアウト後にBefore／After画像が画面に残らない。
- `/server.js`, `/.env`, `/account-store.js` が404になる。
- `/api/session` と `/api/account/history` が未ログイン時401になる。
- キーボードのみで主要メニューとログイン操作ができる。
- 画面幅375pxで横方向にはみ出さない。

## 変更しないファイル

- 画像保存バックエンド
- Geminiプロンプトと生成処理
- クリニックデータの内容
- Firestoreデータ構造

問題を発見した場合は、担当外のコードを大きく直さず、再現手順・期待結果・実際の結果をIssueまたはPRへ記載する。

## 完了条件

1. 全画面で同じナビゲーションが表示される。
2. 未ログイン状態から保護画面を操作できない。
3. PCとスマホでメニューが重ならない。
4. 既存テストと追加テストがすべて成功する。
5. 手動確認表に担当者・日付・結果が記録されている。
6. PRに変更画面のスクリーンショットを添付する。

## 提出物

- 共通ナビゲーション
- 自動テスト
- QA確認表
- 不具合一覧と再現手順
